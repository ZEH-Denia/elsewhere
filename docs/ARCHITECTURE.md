## 技术决策

| 项目 | 决策与原因 |
| --- | --- |
| 前端 | React + TypeScript + Vite，单页应用，保持工程简单 |
| 样式 | Tailwind CSS + 少量全局 CSS；不额外引入大型 UI/动效库 |
| 包管理 | 默认 npm，仅维护 `package-lock.json`；不混用多种锁文件 |
| 运行环境 | 本机 Node v26.13.0、npm 11.20.0；不是已验证的工程兼容组合，Qoder 需核对所选依赖的要求并报告 |
| 页面状态 | 首轮使用组件本地状态；暂不引入路由或全局状态库 |
| 剧情 | 后续采用有类型的本地结构化数据；不把全部分支硬塞进页面渲染逻辑 |
| 持久化 | 首版内存状态即可，刷新从首页开始；暂不保存个人数据 |
| 资源 | 系统字体与本地资源，首轮可用 CSS 营造氛围；不依赖外部 CDN、远程图片或在线接口 |
| 部署 | 目标是静态构建，赛事要求指向 Qoder Sites；部署适配与发布单独验收，TASK-001 不部署 |

Qoder 必须使用真实可安装且相互兼容的版本并保留锁文件，核对 Tailwind 与构建工具的对应配置，不机械照搬旧教程。若需更换 Node 或技术栈，先报告证据，不自行修改全局环境。

## 目录演进建议

以下是实现方向，不要求 TASK-001 创建空目录或预写后续功能：

```text
src/
  App.tsx                页面状态与流程组装
  components/            确有复用需求时再拆分
  screens/               后续来电、对话、时间线、来信视图
  story/                 后续剧情类型、数据、分支映射
  styles/                或沿用 Vite 的样式入口
public/                  确有需要的本地资源
```

已完成的 TASK-001 采用 `home → intro → home`。TASK-002 在此基础上接入来电、对话、首次选择、反馈与本段结束；页面状态名可按实现合理组织，内容与转移需可追踪、可检查。禁止伪造真实连接状态、永久加载或随机选择反馈。
