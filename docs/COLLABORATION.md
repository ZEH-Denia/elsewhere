# 项目协作协议

## 职责与授权

- Codex 负责项目规划、源码与素材实现、验证、审查记录以及 Git 同步。
- 团队负责产品决策、主观体验、批准下一任务和发布。应用合并到 `main`、网站部署、对外发布、赛事投稿以及仓库可见性或权限变更，由团队明确授权。
- 2026-11-16 起，每轮完成检查后自动提交并推送到现有 GitHub 仓库。2026-11-21 起，Codex 直接承担项目工作。既有 Qoder 报告与交接保留原作者及实际结果。

## 每轮工作

1. 阅读 [AGENTS.md](../AGENTS.md)、[当前任务](../tasks/current.md)、该任务的[最新审查](../tasks/reviews/README.md)及相关用稿。
2. 检查本地改动、远程分支和遗留进程。保留未交接的改动，同一时间只有一方写入。
3. 以当前任务为范围。存在 FIX 时先复验问题并修复，沿用任务编号。
4. 核对实际差异并运行与改动相关的检查。记录验收对应的实现提交、环境、浏览器范围、证据和未验证项。
5. 将核对后的文件按分支提交并推送。推送后比对远程提交和本地提交。

## 分支与记录

| 位置 | 用途 |
| --- | --- |
| `main` | 当前任务与审查的权威版本，保存项目约定、说明和归档 |
| 当前任务分支 `task-003` | 应用实现与返修，必要时同步文档副本便于本地查阅 |
| [tasks/reports/](../tasks/reports/README.md) | 既有执行交接、截图及验证证据 |
| [tasks/reviews/](../tasks/reviews/README.md) | Codex 的独立审查，使用 PASS / FIX / BLOCKED |
| `tasks/archive/` | 已完成并归档的任务 |

PASS 表示指定提交及验收范围已经通过。FIX 写清复现、修复要求与复验条件。BLOCKED 写明缺失的信息或环境。任务 PASS 后由团队批准下一项。HTTP 可达、静态代码阅读、构建和交互实测分别记录。

按文件明确暂存，密钥、本机文件、依赖和构建产物留在本地。遇到分支分歧保留现场。仅在存在对应改动时创建提交。项目的早期流程见[历史交接](QODER_START.md)。
