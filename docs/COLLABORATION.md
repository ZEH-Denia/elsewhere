## 单任务闭环

1. Codex 生成 `tasks/current.md`，列明目标、上下文、允许改动、禁止事项、验收与报告要求。
2. 团队把文末最短指令交给 Qoder IDE。执行方读取项目规则，在当前目录按任务开发。
3. Qoder 完成实现与验证，写入 `tasks/reports/TASK-XXX.md`，停止修改并交还审核。
4. Codex 读取真实改动、执行报告与工作区状态，独立检查代码并复跑必要检查，生成 `tasks/reviews/TASK-XXX.md`。
5. FIX：Qoder 按报告最小修复，更新原执行报告的修复记录；Codex 重新审查。BLOCKED：写清阻碍、已尝试项和解除条件。
6. PASS：团队批准后才能进入下一任务。Codex 先将当前任务原文归档到 `tasks/archive/TASK-XXX.md`，再生成下一个 `tasks/current.md`，保留全部报告与审查记录。

## Qoder 执行报告格式

报告写入 `tasks/reports/TASK-XXX.md`，至少包含：

1. 任务编号、执行日期、报告轮次（初次/第 N 次修复）、完成/部分完成/受阻。
2. 实际改动及文件清单，依赖和版本；技术偏离及原因。
3. 验收逐项表：验收编号、实际结果、证据路径或原始输出、未完成原因。
4. 实际验证命令、工作目录、退出码和关键输出；浏览器、视口、交互步骤及观测结果。
5. 浏览器控制台与网络异常、截图路径；无浏览器能力时明确写“未验证”，不可拿构建替代。
6. 已知问题、仍运行的开发服务及地址（如有）、Git 状态/提交号。
7. FIX 时追加修复内容与复验结果，保留原有事实和未解决项。

截图放在 `tasks/reports/assets/TASK-XXX/`，使用本地相对路径引用；不外传项目。不要粘贴包含令牌、个人路径之外敏感数据的完整日志。

## Codex 审核格式

`tasks/reviews/TASK-XXX.md` 包含：状态、审核对象（提交号或工作树/报告轮次）、实际复跑项、未验证项、逐项验收结论、问题严重度与精确文件/行号、修复要求、复验结果。

- P0：泄露、数据损失或无法继续的严重故障。
- P1：无法启动/构建、主流程失效、核心验收缺失。
- P2：适配、可访问性、文案或体验缺陷。
- P3：非阻塞建议，不据此扩展当前任务。

阻塞验收的问题与必要证据缺口解决后才可 PASS；缺少浏览器证据不得声称视觉和交互已通过。审核时仍不代替 Qoder 修改业务代码。
