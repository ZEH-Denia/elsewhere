# GitHub 协作入门

仓库：**[ZEH-Denia/elsewhere](https://github.com/ZEH-Denia/elsewhere)**，当前为公开仓库（2026-11-16 GitHub API 实查）。建立日期：2026-11-16。

## 阅读与协作权限

当前公开仓库可直接阅读或克隆。需要推送改动的组员准备自己的 GitHub 账号，把用户名交给项目负责人，负责人按授权在仓库 Settings → Collaborators 中邀请。当前尚未根据组员名单发送邀请。

只阅读介绍、任务和报告，可以登录后直接在 GitHub 网页打开。手机上也可先查看文档，不必安装开发环境。

## 在自己的电脑获取项目

有 Git 的开发设备，在终端进入自己存放项目的目录，执行：

```sh
git clone https://github.com/ZEH-Denia/elsewhere.git
cd elsewhere
```

推送需要使用已获写入权限的 GitHub 账号认证。使用 GitHub CLI 的同学可先运行 `gh auth login`，再用 `gh repo clone ZEH-Denia/elsewhere`；也可使用 GitHub Desktop 克隆。

将克隆得到的 `elsewhere` 文件夹作为 Qoder IDE 的项目根目录。已存在的本项目目录直接继续使用，无需在其中再次克隆。

## 每次开始前更新

先确认没有未保存工作和未交接改动。开始新任务、需要从 main 创建任务分支时，在仓库目录运行：

```sh
git status
git switch main
git pull --ff-only origin main
```

已有任务分支时在该分支继续，不为拉取而把未交接开发带回 main。若有本地修改、切换失败或拉取失败，保留现场，把输出交给负责人或 Codex；不要用强制覆盖或删除文件来“同步”。Codex/Qoder 按每轮工作流程自动提交推送，组员的其他设备仍需主动拉取更新。

## 后续改动如何汇总？

1. 团队确定当前任务的唯一开发执行人；其他人可以准备剧情和素材、记录体验问题。
2. 执行人在自己的设备用 Qoder 按任务开发，生成执行报告并交 Codex 审核。
3. 持续授权已生效，无需逐次请求同步：每轮开发交接或返修结束，将任务相关改动自动提交到任务分支（例如 `task-001`）并推送；完成可审查实现后发起 Pull Request（PR，合并申请），记录审核所依据的提交号。检查未通过也可备份到任务分支，但必须在报告中如实标明问题。
4. Codex 给出审核意见，执行人处理返修；团队批准后再合并到 `main`。其他组员拉取 `main` 获取已合并结果。

2026-11-16 团队已将初始文档上传授权扩展为“以后有改动都自动同步”。Codex 的指挥文档每轮检查后自动提交、推送 main；Qoder 每轮自动同步当前任务分支。任务范围、代码审核、合并 main、网站发布和投稿边界继续适用。

同步前检查文件清单与远程变化，使用明确的文件名暂存，避免混入其他人的未交接成果。同步后比对远程分支提交与本地提交，确认内容可读取；没有改动不做空提交，遇到拒绝不强推，报告未同步状态。仅本地保存文件不代表同步完成。

只推送源码、依赖锁文件、文档和必要的验收证据；`node_modules/`、`dist/`、本地环境密钥和缓存已由 `.gitignore` 排除。GitHub 仓库用于协作与备份，网站部署另行安排。
