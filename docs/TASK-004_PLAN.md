## 目标与边界

在已验收的 `task-003` 应用基础上，将四种剧情结局自然延伸为 **两条人生时间线 → 来自另一个自己的信 → 重听或回到首页**。双世界应能对照看到各自的收获和困难，两次选择都要在时间线或信中产生可解释的差异；不以好坏结局评判玩家，不预测真实人生。

基线是 `task-003` 的已审查实现 `ddc3239` 及其后的审查文档 `8040b11`（开工前重新 fetch 并确认实际最新提交），不是直接从 `main` 的较早 PR #3 版本重建。PR #3 已合并到 `0cb70cf`，其后的部分视觉、选项预览及一屏布局仍留在 task-003；是否合并到 main 仍按团队权限批准。可从最新经核实的 task-003 派生新任务分支并并入指挥文档，保留既有结果。

本阶段不做后端、AI、账号、支付、分享、追踪、云端/本地存档、自动生成素材、真实通话或新增大型组件库；部署、公开发布和参赛投稿另行授权。Qoder 开发，Codex 负责定稿边界和审核，不直接写业务代码。

## 用户体验流程

1. 保留两次选择及四种不同结局；结局新增明确主操作 **“看看两种人生”**。保留可用的重听和返回首页，主次清楚。
2. 时间线先给出一句引导，并用文字明确标识“现实 · 工程”和“平行 · 音乐”。桌面可并排对照；手机优先逐时间点上下成组展示，玩家无需横向滚动，也能知道同一时期两边发生了什么。
3. 每个时间点两侧分别有短标题和一两句描述；提供真实可用的 **“读另一封信”** 或更自然的“读这封信”。时间线能返回当前结局且不丢选择；返回后再次进入应是同一组合。
4. 信件直接可阅读，清楚标明来自“另一个你”；按四个结局显示对应内容。提供 **“再看时间线”**、**“重听这通来电”** 和 **“返回首页”**。避免在信件里提供不能工作的分享或下载按钮。
5. 重听清空两次选择、节点与结局，从来电页开始并重新接听；返回首页及刷新清空。时间线和信之间往返保留选择，新的体验不得残留旧信件或旧时间线。

允许 Qoder 对具体页面状态名和布局做轻量设计，但内容和选择映射必须与最终用稿一致。不引入必须等待动画、自动跳页或仅能通过鼠标悬停发现的内容。

## 内容和分支规划

现有结局 ID 保持不变：`regret-make-space`、`regret-reach-out`、`cherish-make-space`、`cherish-reach-out`。建立可追踪的数据映射，每种组合都有自己的时间线差异和信件段落；共同段落可复用，但不能只换标题或一两个代词。

| 首次选择 | 第二次选择 | 应体现的叙事重点 |
| --- | --- | --- |
| regret | make-space | 承认遗憾；现实中的一段小练习回应音乐愿望，平行世界也有排练与现实压力 |
| regret | reach-out | 承认遗憾；把心事讲给信任的人，突出被听见，而非假装问题立刻解决 |
| cherish-present | make-space | 珍惜已有生活，同时在日常为喜欢的事保留一点空间 |
| cherish-present | reach-out | 珍惜当下，并通过与身边人沟通建立理解 |

时间点建议使用“那年选择”“各自的现在”“从明天开始”三组相对时间，避免臆造年份、收入、职业成败或现实世界用户经历。第三组是故事中角色的意愿，不写成预测。每组都有现实/平行两侧，至少一处明确回应两次选择；四封信都应回应通话内容、第一项感受及第二项行动。正式交接前由 Codex 准备有编号的中文时间线/四封信执行稿并供团队校订；现有 `STORY_BRANCHES.md` 是 TASK-003 初稿，已被 Excel 润色定稿部分替换，应以当前应用文本及已审查的 Excel 定稿为参考，不倒退旧措辞。未经确认的新增剧情先标草稿，不冒充团队定稿。

## 视觉、可读性与交互要求

- **视觉一致**：延续当前暖米色、雨夜双城、本地插画和轻量转场；时间线/信件是同一叙事世界的延伸，不重新设计首页。背景服务内容而不与正文争夺注意，禁止依赖颜色区分两个世界。
- **文字可读**：正文起点 16–18px、中文合理行距与行长；背景图、渐变和半透明叠层下对正常正文及必要操作文字以实际渲染的 4.5:1 为验收目标。主标题、当前内容、主操作、次操作层级明确。深色/亮色图像区域及四种结局都抽样；必要时调整局部底色或遮罩，不能只用调色板颜色计算代替实际背景。小号装饰标签不承载唯一信息。
- **长文与矮屏**：320×568、390×844 下正文、长信和所有按钮允许自然垂直滚动；不锁高度、不截断、不通过缩小正文字号强塞首屏。桌面 1366×768 / 1440×900 和平板 768×1024 检查不溢出；桌面可滚动的长信优先完整可读，不把一屏放下作为硬条件。检查浏览器原生 200% 缩放；做不到须如实记录，不能把 DOM 字体放大称为原生缩放。
- **交互清楚**：主操作可见且有明确反馈；Tab 顺序符合视觉顺序，Enter/Space 能完成结局→时间线→信→重听；触控目标至少 44×44px。页面切换焦点转到对应标题，返回时恢复合理位置；新内容用清晰标题/语义告知辅助技术，不重复播报整篇信。鼠标悬停、键盘聚焦与触屏都能完成所有操作。
- **动作克制**：延续现有轻量转场但不阻挡阅读、焦点或点击；支持 `prefers-reduced-motion`；避免闪烁、强烈视差和持续运动。背景失效也可读、可操作，不依赖远程字体或网络素材。

## 实施顺序（供正式任务拆解）

1. **内容准备**：以最新实现和定稿为基线，确认三组时间点、四组合差异和四封信，记录团队内容校订与授权。先把映射写成可审查的结构，不提前宣称内容已经定稿。
2. **数据与状态**：将时间线、信件、稳定 ID 和选择映射以类型化本地数据组织；扩展状态而不改写已验收的两次选择。为缺失信件/时间线或非法组合提供明确、安全的恢复，不能随机套用其他人的结局。
3. **页面与交互**：先实现结局到时间线、信与往返重玩；再做双世界对照布局、长文排版与轻量动效。保持当前首页、来电和对话体验。
4. **测试与报告**：用逻辑测试覆盖四组合映射、缺失内容、重置与非法状态；同时用真实生产浏览器从首页走四条路径至信件，并至少一条重听后换另一组合。不能只调用数据函数冒充端到端验收。
5. **审核与团队试玩**：Qoder 在任务分支提交报告、截图和可复验的过程证据，Codex 审核实际代码与关键场景；团队完成主观阅读、视觉与交互体验确认。PASS 后才决定下一步。

## 建议验收清单

- 四组合从首页可完成两次选择、不同结局、对应时间线和不同来信；每封信能明确指出两次选择如何影响内容。
- 时间线两侧身份和时间点不混淆，桌面和手机都能完整阅读；信件全文能滚到最后，主次操作可见、无横向溢出、无图片盖字。
- 往返、重听、返回、刷新、快速点击及中途退出状态正确；不出现陈旧的结局、信件或焦点。至少一条完整键盘路径、可见焦点、reduce 模式及 44px 目标通过。
- 运行 `npm ci`、`npm run typecheck`、`npm run test:story`、`npm run build` 和存在的 lint；保留环境、退出码、实际浏览器与视口、关键截图、控制台和网络结果。只把实际运行的检查写为通过。
- 检查 320×568、390×844、768×1024、1366×768、1440×900，记录长文字、滚动和背景/文字实际对比；实体手机、真实屏幕阅读器或原生缩放未验证时明确披露。
- 保留开发过程、素材来源与任务报告；未修改原始 Excel 或本地未跟踪 Word 剧本。同步指挥文档到 main，开发提交到正式下发的任务分支；网站/投稿不随 Git 自动发布。
